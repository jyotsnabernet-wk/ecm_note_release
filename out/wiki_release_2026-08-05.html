Release Notification

FedRAMP sanitization Iceberg tables, FedRAMP cost optimization, ECM customer OBTs, ECM estimated solution totals

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • FedRAMP Sanitization — Iceberg table exposure for Workiva modules
    • As part of the FedRAMP Sanitization project, all Workiva/Wdesk data must be sanitized before reaching Snowflake; this work builds and exposes sanitized Iceberg tables for four high-volume event modules.
    • Sanitized Iceberg tables have been created and connected to Snowflake for workiva_org, workiva_org_membership, workiva_org_module, and workiva_filing, each backed by an Athena-based pipeline.
    • Every table is covered by unit tests, satisfying the Phase 1 completion criteria for sanitized data availability. (DNA-5885 / DNA-5702 / DNA-5703 / DNA-5721)
  • FedRAMP — Athena cost optimization for Workiva API models
    • Workiva API models have been right-sized by reducing CPU and DPU allocations and removing non-beneficial partitioning to lower monthly Athena spend.
    • This optimization reduces infrastructure costs while maintaining data availability and query performance for downstream consumers. (DNA-5742)
  • FedRAMP — Row access policy for Workiva document federal data
    • A row access policy is being added to the workiva_document table in Snowflake to mask federal organization rows from standard consumers by default.
    • The SUV (Snowflake Universal View) role retains full row access to support Redshift conversion dashboards without exposing federal org data to unauthorized users. (DNA-5887)
  • ECM — Monthly & quarterly customer OBT layer
    • New OBT (One Big Table) models have been built for quarterly and monthly customer facts, joining to dim_accounts and consolidating geo and parent account attributes into the OBT layer.
    • obt_customers_quarterly and obt_customers_monthly replace direct fact-table references in logic views, ensuring all downstream reporting flows through a single, consistent layer.
    • Logic views are re-pointed to the new OBTs, removing duplicated dimension attributes from fct_customers_quarterly and fct_customers_monthly. (DNA-5801)
  • ECM — Estimated solution total field in OBTs
    • A new estimated solution total field is being added to the Salesforce Solution Totals object and has been requested to flow through the gold layer into ECM OBTs.
    • This field is surfaced from source into the ECM OBT layer to provide SalesOps and Finance with updated pipeline value figures in existing reports. (DNA-5676)
  • ECM — Company transfer logic in customer models
    • Key edge cases identified during stakeholder review are being addressed to improve accuracy of the customer dataset, specifically around intracompany transfer scenarios.
    • Logic is being implemented based on agreed acceptance criteria and test cases covering both positive and negative transfer scenarios. (DNA-5674)
  • ECM — Non-PI bookings exclusion fix in OBT Bookings
    • The current OBT_Bookings model incorrectly excludes valid Non-PI Bookings associated with "Never Started" contracts — a filter that should apply only to PI Bookings.
    • Logic is being updated to ensure Non-PI deals are captured correctly, with an impact analysis completed before changes are deployed. (DNA-5717)
  • Customer360 — D&B hierarchy table
    • A new Dun & Bradstreet (D&B) hierarchy table is being built within the Customer360 domain to enrich account-level data with firmographic hierarchy information, enabling richer account segmentation for downstream teams. (DNA-5544)

Why it is happening

FedRAMP compliance & cost efficiency

  • Federal risk and authorization requirements mandate that all Workiva/Wdesk data be sanitized and access-controlled before reaching Snowflake; sanitized Iceberg tables and a row access policy on workiva_document fulfill Phase 1 obligations, while model right-sizing keeps Athena infrastructure costs in check.

ECM reporting accuracy & completeness

  • Finance and SalesOps rely on ECM models for pipeline and customer reporting; the OBT consolidation, estimated solution total field addition, intracompany transfer corrections, and Non-PI bookings fix collectively improve data completeness and reduce the risk of misleading figures in executive dashboards.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-08-05).

Downstream impact

  • Snowflake consumers of workiva_org, workiva_org_membership, workiva_org_module, and workiva_filing will gain access to sanitized, fully tested Iceberg-backed data.
  • All logic views and reports built on fct_customers_quarterly and fct_customers_monthly should be re-validated against the new obt_customers_quarterly and obt_customers_monthly models.
  • Downstream dashboards referencing OBT_Bookings may see row count or aggregate value changes once the Non-PI bookings exclusion fix is deployed.
  • Reports consuming ECM OBTs will gain a new estimated solution total column after this release deploys.

Recommended actions

Verify — Validate that reports and dashboards built on obt_customers_quarterly and obt_customers_monthly reflect correct geo and parent account attributes after the OBT layer migration.

Verify — Confirm that standard Snowflake consumers of workiva_document see federal org rows masked as expected, and that the SUV role retains full row access for Redshift conversion use cases.

Verify — Review downstream bookings reports against OBT_Bookings after the Non-PI exclusion fix to confirm that previously excluded Non-PI deals now appear with correct values.

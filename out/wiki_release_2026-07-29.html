Release Notification

FedRAMP Workiva sanitization, Zendesk fix, ECM bookings, SCD data quality, Customer 360

DnA Release — July 23–29, 2026 | Executive Summary

  • FedRAMP — Five sanitized Iceberg tables for Workiva event data are now live, completing a key Phase 1 compliance milestone.
  • Support Data — A type error in the Zendesk voice calls model is resolved, restoring full data availability for support reporting.

Need more detail? Review the technical release notes here: DNA Weekly Release Sprint 7/23-7/29

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • FedRAMP — Workiva event data sanitization
    • As part of the FedRAMP Sanitization project, all Workiva/Wdesk high-volume event data must be sanitized and exposed via Iceberg tables before reaching Snowflake as a Phase 1 requirement.
    • Sanitized Iceberg tables and unit tests have been delivered for five data streams: workiva_org_membership, workiva_org_module_transform, workiva_retention, workiva_service_provider, and workiva_role_assignment.
    • Each table is connected to Snowflake and covered by unit tests, confirming Phase 1 completeness for these streams. (DNA-5705 / DNA-5706 / DNA-5707 / DNA-5708 / DNA-5722)
  • Support Data — Zendesk voice calls type error
    • A type error in the Zendesk voice calls model was preventing the table from returning data via SELECT.
    • The fix ensures the model is fully queryable and support reporting data is uninterrupted. (DNA-5724)
  • ECM — Bookings logic & renewal metrics
    • The OBT_Bookings model currently excludes all bookings tied to Never Started contracts; while correct for PI Bookings, this logic incorrectly filters out valid Non-PI Bookings and is being corrected. (DNA-5717)
    • A new solution-level renewal metric is being built on the Customers ARR stack, delivering S&S renewal ARR and renewal rate at solution grain, driven by contract term end events. (DNA-5690)
  • Data Platform — SCD integrity, dbt standards & dimensional modeling
    • A preventive dbt_utils.expression_is_true test enforcing version_start_at < version_end_at is being added across 11 SCD Type 2 dimension models including dim_accounts, dim_contacts, and dim_contracts, catching invalid date intervals at build time. (DNA-5712)
    • Work is underway to define and standardize dbt repository and project structures across the analytics engineering estate, aligned to a data mesh architecture for scalable domain ownership. (DNA-3977)
    • A formal review of dimensional modeling standards is in progress to identify gaps against industry best practices and ensure models are optimized for performance, scalability, and reusability. (DNA-3935)
    • A privilege assessment is underway to review and remediate P1 access items across the analytics platform. (DNA-3293)
  • Customer 360 & Salesforce — master data & account attributes
    • A new D&B hierarchy table is being created to enrich Customer 360 with company hierarchy context for improved account intelligence. (DNA-5544)
    • Two deliverables are in progress to establish Workiva Master Account ID and Workiva Master Attributes as foundational customer datasets. (DNA-4362 / DNA-4363)
    • The account_s_s_amt_usd field in dim_salesforce_account is being revised to pull the Account S&S value directly from Salesforce instead of computing a sum of Solution S&S, improving field-level accuracy. (DNA-2227)
  • GTM Analytics — Bookings design & solution classification
    • The int_solution_classifications model is being updated to default null Booking Category and Solution Group values rather than excluding them, ensuring more complete coverage in OBT_Booking and OBT_Pipeline. (DNA-4539)
    • A formal bookings design review is underway to certify company booking logic, covering the full booking lifecycle and alignment with standard SaaS metrics. (DNA-3936)
  • OpenAir — Write-off billing rules
    • Write-off billing rules in OpenAir carry end dates that are no longer valid; a mass removal of these end dates is being executed via UPLOAD_OA_FIN to ensure rules remain active as intended.
    • All reserve hour portfolios will be confirmed to have an active write-off rule in place. (DNA-1113)
  • Analytics Engineering — Partner, CPX & corporate metrics
    • Q1 and Q2 Analytics Engineering workstreams covering Partner Engagement Optimization, CPX Metrics, and Corporate Metrics datasets remain in progress across multiple quarters. (DNA-1691 / DNA-1705 / DNA-934 / DNA-885)

Why it is happening

FedRAMP compliance & data security

  • Regulatory requirements mandate that all Workiva/Wdesk event data be sanitized before landing in Snowflake; the five Iceberg tables completed this release fulfill Phase 1 obligations and unblock downstream analytics on compliant, audit-ready data.

Revenue & data quality improvements

  • Correcting the Non-PI Bookings exclusion in OBT_Bookings, defaulting null solution classifications in int_solution_classifications, and adding SCD Type 2 interval tests all reduce silent data gaps that distort revenue, pipeline, and retention reporting.
  • Building solution-level renewal metrics on the Customers ARR stack gives Finance and Customer Success a consistent, auditable view of renewal performance aligned to the existing retention model.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-07-29).

Downstream impact

  • FedRAMP sanitization exposes five new Iceberg-backed tables — workiva_org_membership, workiva_org_module_transform, workiva_retention, workiva_service_provider, and workiva_role_assignment — now queryable from Snowflake for the first time.
  • The Zendesk voice calls model is restored to full selectability, unblocking downstream support dashboards and reports consuming that table.
  • Once deployed, the Non-PI Bookings fix in OBT_Bookings will increase row counts for non-PI deals; consumers should validate aggregate totals against prior baselines.
  • The null-classification fix in int_solution_classifications will change row coverage in OBT_Booking and OBT_Pipeline for solutions with previously excluded null Booking Categories.
  • SCD Type 2 interval tests on dim_accounts, dim_contacts, dim_contracts, and eight additional dimension models will cause dbt build failures if invalid or overlapping date intervals are detected.
  • The account_s_s_amt_usd field in dim_salesforce_account will reflect the direct Salesforce Account S&S value rather than a calculated sum, potentially changing values for accounts with multiple solutions.

Recommended actions

Verify — After deploy, validate Non-PI Booking row counts and aggregate ARR in OBT_Bookings against the prior release baseline to confirm the Never Started exclusion fix is accurate and complete.

Verify — Confirm downstream dashboards and reports consuming OBT_Booking and OBT_Pipeline reflect updated totals after the null solution classification change goes live.

Verify — Confirm the five new FedRAMP Iceberg tables are accessible in Snowflake and all unit tests are passing in the CI/CD pipeline post-deploy.

Release Notification

FedRAMP Athena and Snowflake readiness, customer activity models, user analytics performance, PnC data discovery

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • FedRAMP — daily history cleanup fix and pipeline linkage
    • The dbt Athena post hook for daily history cleanup is fixed. It previously failed because not every model was on table version 2 and because of a map key incompatibility in user_analytic.
    • Daily cleanup now runs without those failures, so history can be cleaned up as Federal customers change.
    • Work continues to link dbt Athena to dbt Snowflake for Iceberg tables. Snowflake typically breaks when the upstream Athena process does a full replacement or table drop, even with AUTO_REFRESH = true. The goal is to run DDL after hourly runs using macros and config files, with no manual relationship maintenance (DNA-6621 / DNA-6663).
  • FedRAMP — Snowflake parity checks for user analytics
    • Row-count parity analyses in Snowflake are in progress for the User Analytic Live and User Analytic History tables. They confirm the tables match 1:1 and that timestamps are in UTC.
    • These tables hold billions of rows, so comparisons may need ranges smaller than monthly to avoid query timeouts (DNA-6623 / DNA-6622).
  • FedRAMP — runbooks for Amplitude and Wdesk Classic models
    • README runbooks are being created in the repo for the Amplitude and Wdesk Classic models in dbt Athena, using an AI tool to draft them.
    • Each runbook covers how to rerun the hourly refresh and the daily run, how to correct history, and how to backfill it. Each also covers the extra steps needed if the models must be fully refreshed (DNA-6638 / DNA-6628).
  • FedRAMP — role permission parity for sanitized tables
    • Role grants on the new Workiva, Amplitude, and GES tables are being compared with the existing grants, with the exception of ownership.
    • Any grants that do not match will be run so security is identical across the sanitized tables (DNA-6636 / DNA-6637 / DNA-6642).
  • Product usage — feature events and shared customer activity spine
    • A new fct_feature_events model is being built with one row per raw event and feature event. feature_event_key is a hash of event_key and feature_event_name, so a raw event matching two rules for the same feature event is stored once.
    • Employees, internal workspaces, and non-production environments stay on this fact, and population filters are applied downstream. A macro reads feature_event_rules() and generates one select per rule.
    • fct_user_workspace_usage_daily is being updated to serve as the shared daily customer activity spine for product usage reports. Today it still keeps employees, unknown users, internal workspaces, internal organizations, and days with a missing workspace or organization, so each report has to remove those rows again (DNA-6490 / DNA-6495).
  • User analytics — query performance investigation
    • A timeboxed investigation is looking at why queries against the silver_prod.user_analytic views time out. The views apply filters after a full table scan, which makes even simple queries expensive.
    • Analysis across all event types is also difficult today, because the data is spread across the event type views in Snowflake (DNA-6093).
  • PnC — Snowflake dataset discovery
    • A timeboxed discovery is under way to find what PnC data already exists in Snowflake. It will support the Headcount and Talent Acquisition efforts (DNA-6656).

Why it is happening

FedRAMP & platform reliability

  • Federal customer data must be kept accurate, cleaned up daily, and consistent between Athena and Snowflake without manual upkeep.
  • Parity checks, matching role grants, and runbooks give the team evidence of data and security equivalence. They also give operators clear recovery steps when hourly or daily runs fail.

Product & customer analytics

  • A shared, pre-filtered activity spine and a rule-driven feature events fact remove the need for each product usage report to re-apply the same exclusions.
  • The user analytics and PnC investigations clarify where performance and data coverage gaps are before more models are built.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-11-11).

Downstream impact

  • Product usage reports that read fct_user_workspace_usage_daily may see fewer rows once employees, unknown users, internal workspaces and organizations, and days with missing workspace or organization are excluded.
  • The new fct_feature_events model adds a feature event fact that keeps employee, internal, and non-production events. Downstream consumers must apply their own population filters.
  • Federal Athena and Snowflake models, including user_analytic, depend on the corrected daily history cleanup post hook and on Iceberg table linkage after hourly refreshes.

Recommended actions

Verify — after the deploy, daily Athena post hook runs for the FedRAMP models complete without table version or user_analytic map key errors.

Verify — product usage dashboards that use fct_user_workspace_usage_daily still reconcile once internal and unknown rows are excluded.

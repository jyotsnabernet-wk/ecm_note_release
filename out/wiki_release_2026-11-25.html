Release Notification

FedRAMP parity &amp; cutover, user analytics consolidation, FX rates, GES ingestion fix, workspace modules, absences

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • FedRAMP — parity checks, backups, and production cutover
    • Row-count parity analyses between legacy and FedRAMP tables were completed for Workiva and GES sources, comparing counts by month and checking whether differences come from duplicates or missing rows. Rechecks for GES are finished for parts 1 and 2, and part 3 is still in progress.
    • The WDesk Classic production cutover (part 1) replaced legacy table references in dbt with their FedRAMP equivalents, validated through compile-focused QA in a personal SILVER_TEST schema. The matching Workiva cutover (part 1) is still in progress.
    • A sanitized historical backup of user analytics data was unloaded to S3, partitioned by year and month, to support disaster recovery if the table is accidentally dropped.
    • The Amplitude history leakage notebook was run over 4/17/2026 to the present in roughly five-day chunks to identify any days with leaked data, and the results table was verified as populated. (DNA-6304 / DNA-6582 / DNA-6583 / DNA-6584 / DNA-6436 / DNA-6831 / DNA-6821 / DNA-6729)
  • Product usage analytics — consolidated gold event model
    • Legacy USER_ANALYTIC event tables that BI and CPX previously read from silver full-scan dedupe views were added to the user_analytics_lake_events allow list and are now built through fct_user_analytics_events, so consumers query gold instead of silver.
    • A new product_usage_full_refresh variable (default false) keeps fct_user_analytics_events, fct_ges_events and fct_feature_events incremental under production CI --full-refresh runs, preventing timeouts caused by rebuilding from product_usage_start_date.
    • Amplitude region codes (us, eu, apac, ca) are now normalized to Workiva environment names (production, prod-eu, prod-apac, prod-ca) when building fct_feature_events, so Amplitude rows join correctly to fct_user_workspace_usage_daily and workiva_user.
    • Retirement of the grouped int_user_analytics_ intermediate layer, along with the macros and seeds that exist only to build it, is in progress now that product usage flows through fct_user_analytics_events. (DNA-6744 / DNA-6808 / DNA-6792 / DNA-6735)
  • FX Rates — additional Oanda currency pairs
    • Three currency pairs (USD/MXN, USD/COP, USD/CHF) were added to the Oanda FX rates feed in OANDA_RATES_CANDLE, with history loaded back to July 1, 2022.
    • The new pairs were also added to the related gold views so Finance can use them in currency reporting. (DNA-6823)
  • GES ingestion — hourly S3 COPY fix
    • The load_staging_hourly DAG built its S3 folder path from the date at DAG parse time, so after midnight UTC the previous day's folder was never read again.
    • Files landing after the last 23:00 UTC run of each day could therefore be missed when copying GES topics into LAKE_PROD.GES. The fix ensures those late files are loaded. (DNA-6468)
  • Workspace modules — Type 2 SCD dimension
    • A new gold model, dim_workspace_modules, is being built as a table following the Type 2 SCD pattern with version_start_at, version_end_at and is_latest.
    • It is sourced from silver workiva_workspace_module_history, enabling point-in-time lookups and current-state filtering. (DNA-6674)
  • People & Culture — absences fact table
    • A new absences fact table is in progress to supply absence information required by many headcount dimensions. (DNA-6784)

Why it is happening

FedRAMP readiness

  • Parity checks, a disaster-recovery backup and leakage review reduce risk before production references are cut over to FedRAMP sources.
  • Replacing legacy table references in dbt keeps downstream models compiling cleanly against the new environment.

Reliable, consistent analytics

  • Consolidating usage events in gold and normalizing environment names makes product usage reporting consistent and joinable across customer activity models.
  • Keeping usage facts incremental under CI and fixing the hourly S3 COPY gap avoids timeouts and missing data, and new FX pairs and dimensions extend reporting coverage.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-11-25).

Downstream impact

  • Product usage consumers (BI and CPX) should read the newly added USER_ANALYTIC event tables from fct_user_analytics_events in gold instead of silver dedupe views.
  • fct_feature_events Amplitude rows now carry Workiva environment names, which affects joins to fct_user_workspace_usage_daily and workiva_user.
  • Production CI runs that rebuild fct_user_analytics_events, fct_ges_events and fct_feature_events now stay incremental unless product_usage_full_refresh is enabled.
  • Finance FX reporting sourced from OANDA_RATES_CANDLE and the related gold views now includes USD/MXN, USD/COP and USD/CHF.
  • GES tables in LAKE_PROD.GES will now include files that previously landed after the last hourly run of a UTC day.

Recommended actions

Verify — Amplitude-sourced rows in fct_feature_events join to fct_user_workspace_usage_daily and workiva_user using production, prod-eu, prod-apac and prod-ca.

Verify — BI and CPX queries previously reading USER_ANALYTIC silver views return expected results from fct_user_analytics_events.

Verify — USD/MXN, USD/COP and USD/CHF appear in OANDA_RATES_CANDLE and the related gold views with history back to July 1, 2022.

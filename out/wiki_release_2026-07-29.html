Release Notification

FedRAMP Workiva sanitization, Zendesk fix, ECM bookings &amp; renewals, C360 D&amp;B hierarchy, SCD Type 2 quality

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • FedRAMP — Workiva sanitized Iceberg tables
    • As part of the FedRAMP Sanitization project, all Workiva/Wdesk event data must be sanitized before reaching Snowflake; five high-volume modules required sanitized Iceberg tables and unit test coverage before Phase 1 is considered complete.
    • Sanitized Iceberg tables have been built and connected to Snowflake for workiva_org_module_transform, workiva_service_provider, workiva_role_assignment, workiva_retention, and workiva_org_membership.
    • Unit tests have been added to each module to validate data quality and confirm completeness of the sanitization pipeline. (DNA-5705 / DNA-5706 / DNA-5707 / DNA-5708 / DNA-5722)
  • Zendesk — voice calls type error fix
    • A type error in the Zendesk voice calls model was preventing data from being returned on SELECT queries, blocking support analytics consumers.
    • The fix restores full data accessibility so downstream reporting and exports behave as expected. (DNA-5724)
  • ECM — non-PI bookings logic correction
    • The current bookings logic in OBT_Bookings excludes all bookings associated with Never Started contracts; while this exclusion is correct for PI Bookings, it incorrectly filters out valid Non-PI Bookings.
    • The logic is being updated so that Non-PI deals are captured appropriately, improving completeness of pipeline reporting for Finance and RevOps. (DNA-5717)
  • ECM — solution renewal metrics
    • New solution-level renewal metrics will measure S&S renewals at contract term end, using the Customers ARR stack — the same subscription population as the daily fact — as the retention model.
    • Deliverables include a detail fact model for renewal events at solution grain, exposing S&S ARR up for renewal and renewal rate for Finance stakeholders. (DNA-5690)
  • Customer360 — D&B hierarchy table
    • A new Dun & Bradstreet hierarchy table is being built as part of the Customer360 initiative to enrich account data with corporate hierarchy information, supporting account segmentation and analysis. (DNA-5544)
  • Platform — SCD Type 2 dbt data quality tests
    • A preventive dbt_utils.expression_is_true test is being added to SCD Type 2 dimension models to enforce that version_start_at < version_end_at on every row, catching interval problems at build time before they reach downstream consumers.
    • Eleven models are in scope, including dim_accounts, dim_contacts, and dim_contracts. (DNA-5712)

Why it is happening

FedRAMP compliance

  • Workiva/Wdesk event data must be sanitized before landing in Snowflake as a prerequisite for FedRAMP Phase 1 certification; five high-volume modules required sanitized Iceberg tables and unit test coverage to satisfy the Phase 1 definition of done.

Data quality & analytics completeness

  • A type error in the Zendesk voice calls model was blocking support analytics data access and required an immediate fix to restore reporting fidelity.
  • ECM bookings logic must be corrected to stop valid Non-PI deals from being silently excluded, and new solution-level renewal metrics are needed to give Finance a complete view of S&S retention performance.
  • Adding SCD Type 2 interval tests across eleven dimension models provides a build-time safety net that prevents silent data corruption from propagating into downstream metrics and reports.
  • The D&B hierarchy table expands the Customer360 dataset with corporate structure data required for account segmentation and multi-entity analysis.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-07-29).

Downstream impact

  • FedRAMP-scoped consumers gain access to sanitized, Snowflake-connected data for workiva_org_module_transform, workiva_service_provider, workiva_role_assignment, workiva_retention, and workiva_org_membership.
  • Support analytics workflows querying the Zendesk zendesk_voice_calls model will return correct results after the type error is resolved.
  • ECM reporting surfaces downstream of OBT_Bookings will reflect updated Non-PI booking counts once the never-started exclusion logic is corrected.
  • Finance and RevOps dashboards will gain new solution-level renewal metrics sourced from the new ECM renewal detail fact model built on the customers_arr_stack.
  • All eleven SCD Type 2 dimension models — including dim_accounts, dim_contacts, and dim_contracts — will enforce row-level interval integrity at every dbt build.

Recommended actions

Verify — FedRAMP-scoped data consumers can SELECT from each newly exposed sanitized Iceberg table in Snowflake after the 2026-07-29 deploy.

Verify — Zendesk voice calls data is fully accessible with a SELECT * on the repaired model and downstream support reports return expected row counts.

Verify — ECM Non-PI booking counts in downstream reports reflect the corrected never-started exclusion logic and previously missing deals are now present.

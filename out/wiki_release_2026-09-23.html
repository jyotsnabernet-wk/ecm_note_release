Release Notification

ECM Pipeline Alignment, Salesforce Hierarchy Table, Reference Table Performance Tuning

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • ECM — qualified pipeline model alignment with Marketing
    • An audit comparing the Marketing Ops table against the DNA model revealed a structural scope discrepancy in fct_qualified_pipeline_generated for opportunities with qualified dates from 2023 onward.
    • Although both models calculate value identically for overlapping opportunities, definition differences caused Finance and RevOps to see a smaller opportunity set than Marketing. The model has been updated to resolve the scope gap and align with Marketing's definition. (DNA-6096)
  • ECM — renewal logic enhancements for complex deal structures
    • The fct_solution_renewals model requires logic updates to handle three scenarios surfaced in stakeholder feedback: mid-cycle (early) renewals, granular ARR risk tracking across multiple subscriptions within a single solution, and solution swaps (records where churn_reason = 'Exchanged Solution').
    • These gaps are also present in the related raw renewal tables, so fixes will be applied consistently across the renewal data layer. Work is in progress. (DNA-6222)
  • ECM — contract fields added to OBTs
    • New contract-level fields are being introduced to the ECM opportunity-based tables (OBTs) to support expanded revenue and contract reporting requirements.
    • Scope is being finalized with stakeholders; implementation is in progress. (DNA-6119)
  • Data Platform — Salesforce account hierarchy scheduled table
    • Salesforce account hierarchy mappings were previously retrieved via a resource-intensive Splunk query that caused Splunk to become unresponsive during execution.
    • A persistent scheduled table is being built to replace that query, improving reliability and satisfying a legal data requirement for FIGMA-related account hierarchy lookups. (DNA-5990)
  • Data Platform — reference table performance tuning
    • The most upstream reference tables were reviewed and their materializations and deduplication logic updated to improve query efficiency.
    • The changes are scoped to ensure reference tables perform reliably within hourly dbt Cloud CI jobs. (DNA-6217)
  • Customer 360 — crosswalk validation
    • The Customer 360 crosswalk table is being analyzed to validate entity-mapping accuracy and demonstrate the integrity of records linked across source systems. (DNA-6136)
  • Platform — Canada production environment in Snowflake Silver
    • Workiva is introducing a new Canada production environment (prod-ca) that requires updates to the production_workiva_environments dbt seed and associated user analytic views in Snowflake Silver.
    • Once complete, reporting off the Canadian appspot will be enabled for all Silver-layer consumers. (DNA-6002)
  • Orchestration Migration — Overlord to Airflow & Fivetran assessment
    • A structured migration planning workstream is underway to transition from the Overlord orchestration system to Airflow (MWAA) and Fivetran, covering source inventory classification, MWAA deployment auditing, and specialty behaviour documentation.
    • Every Overlord source is being classified as standardized or custom, and FedRAMP-regulated sources (e.g. Workday) are being flagged to drive the migration wave plan and compliance handling design.
    • Fivetran's current license, active connectors, spare capacity, and the 2026 MAR cost model changes (deletes now count; $5 per-connector minimum) are being documented to optimize connector usage. (DNA-6053 / DNA-6054 / DNA-6055 / DNA-6056)
  • Zendesk — Knowledge Base engagement field ingestion
    • The Zendesk article ingestion pipeline is being extended to pull engagement fields — views, comments, subscriptions, and upvotes — that are currently absent from both the Redshift and Snowflake zendesk.article tables.
    • These fields are required by the DX team to understand how users interact with Knowledge Base content. (DNA-5171)

Why it is happening

Data quality & stakeholder alignment

  • Marketing, Finance, and RevOps depend on consistent pipeline and renewal metrics; structural mismatches in fct_qualified_pipeline_generated and missing edge-case logic in fct_solution_renewals created reporting gaps that stakeholders escalated for resolution.
  • Salesforce account hierarchy data was served via an unstable Splunk query; a scheduled table delivers a reliable, legally compliant source for FIGMA and related downstream workflows.

Platform reliability & migration readiness

  • Reference table performance tuning reduces unnecessary compute overhead in hourly CI runs, improving overall pipeline stability and cost efficiency.
  • The Overlord-to-Airflow migration assessment ensures that bespoke orchestration behaviours are preserved, FedRAMP-regulated sources are handled appropriately, and the team enters the migration with a clear wave plan and tooling cost model.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-09-23).

Downstream impact

  • fct_qualified_pipeline_generated — updated scope aligns with Marketing Ops definitions; all downstream pipeline dashboards and reports will reflect the corrected opportunity set.
  • fct_solution_renewals — mid-cycle renewal, multi-subscription ARR risk, and solution-swap logic changes will affect renewal dashboards and ARR waterfall reports consuming this model.
  • Salesforce account hierarchy scheduled table — FIGMA workflows and any report relying on account hierarchy mappings will read from the new scheduled table instead of the legacy ad-hoc Splunk query.
  • Reference tables — updated materializations and deduplication logic affect all models that join upstream reference data; hourly dbt Cloud CI run times are expected to decrease.
  • production_workiva_environments seed & user analytic views — addition of the prod-ca environment will surface Canada data across all Silver-layer models that filter on environment.
  • zendesk.article — once engagement fields are ingested, DX team dashboards and Knowledge Base analytics will gain access to views, comments, subscriptions, and upvote counts.

Recommended actions

Verify — Marketing Ops, Finance, and RevOps stakeholders should validate pipeline opportunity counts against fct_qualified_pipeline_generated after the 2026-09-23 deploy to confirm alignment with Marketing definitions.

Verify — Renewal reporting consumers should review ARR risk totals and renewal record counts in fct_solution_renewals once mid-cycle renewal and solution-swap logic ships, paying particular attention to multi-subscription solutions and records with churn_reason = 'Exchanged Solution'.

Verify — Any team querying Salesforce account hierarchy data should confirm that downstream queries reference the new scheduled table rather than the legacy Splunk source after the deploy.

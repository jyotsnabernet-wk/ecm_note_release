Release Notification

ECM bookings fields, User Analytics dimension &amp; int layer, Zendesk KB engagement, C360 D&amp;B/ZoomInfo join, dbt docs POC

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • ECM — bookings field enrichment
    • The bookings tables are being extended to include opportunity_creator_id and opportunity_creator_name as they appear in the pipeline view.
    • An opportunity_closed_reason field is also being added to support downstream sales reporting and closed-deal attribution.
    • These additions improve data completeness for ECM pipeline analysis and revenue operations reporting. (DNA-5550)
  • User Analytics — dimension table & intermediate layer expansion
    • A new dim_workiva_users dimension model is being created as the single source of truth for user-related attributes across the platform, formalizing the migration away from the legacy workiva_user model. (DNA-5535)
    • Building on DNA-5519, this release ships 82 additional legacy USER_ANALYTIC tables across 10 new int_user_analytics_* model groups, advancing intermediate layer coverage toward the full 811-table inventory.
    • Each group follows the established int contract (event_key, legacy_table_name, source_event_id, event_timestamp, raw_event_properties); six high-volume tables remain deferred pending Amplitude/User Analytics mapping resolution. (DNA-5534)
  • Zendesk — knowledge base engagement ingestion
    • The zendesk.article ingestion pipeline is being extended to capture engagement fields — views, comments, subscriptions, and upvotes — that are currently absent from both the Redshift and Snowflake versions of the table.
    • These fields are available in the Zendesk Knowledge Base API but are not pulled in through Fivetran, requiring a custom ingestion extension.
    • The DX team needs this data to quantify how users engage with knowledge base content and to inform content strategy. (DNA-5171)
  • Customer 360 — D&B & ZoomInfo account join
    • A new table is being built within the Customer 360 domain to join Dun & Bradstreet and ZoomInfo firmographic data at the account level.
    • This enriched surface will improve account-level segmentation and firmographic coverage for GTM analytics and pipeline reporting. (DNA-5324)
  • Platform Engineering — dbt documentation POC
    • A time-boxed proof-of-concept investigated workarounds for referencing .md documentation files within .sql files, a capability not natively supported by dbt and needed specifically for semantic views.
    • Findings from this investigation will inform future documentation authoring standards for the analytics engineering platform. (DNA-5556)

Why it is happening

Platform data quality & standardization

  • Formalizing dim_workiva_users as a dimension and continuing the int_user_analytics_* intermediate layer buildout reduces reliance on legacy tables, establishes consistent model contracts, and enables reliable downstream KPI tracking and product analytics.
  • The dbt documentation POC addresses a persistent authoring gap — enabling inline documentation for semantic views improves model discoverability and reduces knowledge silos across the engineering team.

GTM & customer analytics enrichment

  • Enriching ECM bookings tables with creator attribution and closed-reason data directly supports sales pipeline accuracy and revenue attribution reporting.
  • Extending Zendesk knowledge base engagement ingestion and building the C360 D&B/ZoomInfo join table deliver incremental improvements to customer support analytics and account-level firmographic data coverage for GTM teams.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-07-08).

Downstream impact

  • Models referencing the legacy workiva_user table should begin migrating to dim_workiva_users; any downstream model joining on user attributes will benefit from the standardized dimension grain.
  • Downstream consumers of int_user_analytics_* model groups gain coverage of 82 additional legacy event tables; models dependent on the six deferred high-volume tables are unaffected in this release.
  • Reports and models reading ECM bookings tables will have access to new opportunity_creator_id, opportunity_creator_name, and opportunity_closed_reason columns after deploy.
  • Any model or dashboard sourcing zendesk.article will gain views, comments, subscriptions, and upvotes engagement fields once the ingestion extension is live.
  • The new C360 D&B/ZoomInfo join table will be available as an additive source for GTM segmentation, account enrichment, and firmographic coverage models.

Recommended actions

Verify — confirm dim_workiva_users row counts and user attributes match the legacy workiva_user model post-deploy; validate new ECM bookings columns (opportunity_creator_id, opportunity_creator_name, opportunity_closed_reason) are populated for recently closed opportunities; and spot-check zendesk.article in both Redshift and Snowflake for the presence of the four new engagement fields.

No action required for teams not consuming ECM bookings, Zendesk article, User Analytics intermediate models, or Customer 360 account tables — the dbt docs POC produces no model changes and all other additions are fully additive.

Release Notification

FedRAMP Workiva sanitization, ECM bookings &amp; renewals, Zendesk fix, SCD Type 2 tests, C360 hierarchy

What is happening

This week's DnA release covers the following Analytics Engineering stories.

  • FedRAMP — Workiva event data sanitization
    • As part of the FedRAMP Sanitization project, all Workiva/Wdesk event data must be sanitized before reaching Snowflake.
    • Sanitized Iceberg tables have been built and exposed for five high-volume Workiva event streams: org module transform, service provider, role assignment, retention, and org membership.
    • Each table is connected to Snowflake and covered by unit tests, satisfying Phase 1 completion criteria. (DNA-5706 / DNA-5708 / DNA-5722 / DNA-5707 / DNA-5705)
  • ECM — bookings accuracy & renewal metrics
    • The never-started contract exclusion in OBT_Bookings incorrectly filters out valid Non-PI bookings; the logic is being corrected so only PI bookings are subject to the exclusion. (DNA-5717)
    • A new solution-level renewal metric is being built on the Customers ARR stack, delivering S&S renewal ARR and renewal rate at solution grain via a new detail fact model. (DNA-5690)
  • Customer360 & Workiva Master — account hierarchy & master data
    • A new Dun & Bradstreet (D&B) hierarchy table is being created in C360 to enrich account relationship data for downstream segmentation. (DNA-5544)
    • Two Workiva Master deliverables are in progress: establishing a canonical Workiva Master Account ID and a comprehensive Workiva Master Attributes dataset to support cross-system account resolution. (DNA-4362 / DNA-4363)
  • Data Platform — SCD Type 2 integrity tests & solution classification
    • A preventive dbt_utils.expression_is_true test is being added to 11 SCD Type 2 dimension models to catch interval overlaps where version_start_at is not strictly less than version_end_at. (DNA-5712)
    • The int_solution_classifications model is being updated to default null Booking Category and Solution Group values, preventing records from being silently excluded in OBT_Booking and OBT_Pipeline. (DNA-4539)
    • The account_s_s_amt_usd column in dim_salesforce_account is being revised to pull directly from Salesforce rather than aggregating solution-level S&S amounts. (DNA-2227)
  • Zendesk — voice call data fix
    • A type error in the Zendesk voice calls model causes query failures; the fix ensures the model returns complete, queryable data for all support call records. (DNA-5724)
  • OpenAir — billing rule cleanup
    • End dates on write-off billing rules in OpenAir are being removed, as the original business rationale for those dates is no longer valid.
    • All reserve hour portfolios will be verified to have an active write-off rule, and the UPLOAD_OA_FIN process will be updated to reflect the corrected configuration. (DNA-1113)
  • Platform Standards — dbt repo, dimensional modeling & access governance
    • Standardized dbt repository and project structures are being defined across the analytics engineering estate to align with a data mesh architecture and enable clear domain ownership. (DNA-3977)
    • The Dimensional Modeling Standard is under review to identify gaps against industry best practices and ensure models are optimized for performance, scalability, and reusability. (DNA-3935)
    • The Booking Design is being reviewed and certified to accurately capture the full booking lifecycle and align with company SaaS metrics. (DNA-3936)
    • A Privilege Assessment is under way to review and remediate P1 access items across the data platform. (DNA-3293)
  • Analytics Engineering — CPX, corporate & partner metrics
    • Q1 and Q2 CPX Metrics are in development to support customer and partner experience reporting across business segments. (DNA-885 / DNA-1705)
    • Q1 Corporate Metrics and Q2 Partner Engagement Optimization datasets are being built to enable cross-functional performance tracking. (DNA-934 / DNA-1691)

Why it is happening

Compliance & data security

  • The FedRAMP Phase 1 program requires all Workiva/Wdesk event data to be sanitized before landing in Snowflake; creating sanitized Iceberg tables for each high-volume event stream fulfills this regulatory obligation and unblocks downstream analytics consumers.

Data accuracy & platform quality

  • Incorrect bookings exclusion logic, missing solution classifications, and a type error in support call data erode trust in key revenue and customer metrics; these corrections ensure Finance, RevOps, and CX teams work from accurate, complete datasets.
  • Preventive data tests on SCD Type 2 models and standardized dbt repository structures reduce the risk of silent data corruption and improve engineering velocity across all domains.

When it will happen

Deploy on

Consumers relying on any changed columns should validate and update downstream references within 30 days of the deploy (2026-07-29).

Downstream impact

  • Snowflake consumers of Workiva event data should migrate to the new sanitized Iceberg-connected tables for workiva_org_module, workiva_service_provider, workiva_role_assignment, workiva_retention, and workiva_org_membership.
  • OBT_Bookings will reflect corrected Non-PI booking counts once the never-started exclusion logic is updated to apply only to PI bookings.
  • A new renewal detail fact model will surface S&S renewal ARR and renewal rate at solution grain, extending the Customers ARR stack for ECM reporting.
  • OBT_Booking and OBT_Pipeline will include previously excluded records once int_solution_classifications defaults null booking categories and solution groups.
  • dim_salesforce_account will return a revised account_s_s_amt_usd value sourced directly from Salesforce, affecting any report that aggregates account-level S&S.
  • The Zendesk voice calls model will be fully queryable after the type error fix, restoring data availability for support analytics dashboards.
  • All 11 SCD Type 2 dimension models — including dim_accounts, dim_contacts, and dim_contracts — will enforce interval integrity via the new dbt_utils.expression_is_true test.

Recommended actions

Verify — downstream Snowflake consumers of Workiva event data are pointed to the new sanitized Iceberg-connected tables after the 2026-07-29 deploy.

Verify — ECM Non-PI Booking counts in OBT_Bookings align with expected values once the never-started exclusion fix is live.

Verify — the Zendesk voice calls model returns complete data via SELECT * following the type error fix.
